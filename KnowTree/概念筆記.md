# KnowTree — 知識樹學習 App（概念筆記）

> 這份筆記記錄構想、決策與理由，之後要繼續做時不會忘記當初為什麼這樣決定。
> 建立日期：2026-10-02

## 一句話構想

當我要學一門新知識（例如為了火箭社學火箭科學、為了賽車社學賽車工程），
讓 AI 幫我產出一棵「知識樹」：每個節點是一門要學的知識、標好前後依賴，
點進節點能看到 AI 從真實搜尋結果篩選過的學習資源與順序。
一棵樹 = 一個可達成的目標（造火箭、造賽車）。目的是省下自己找資料、
規劃學習路徑的時間。進階目標：把學習進度自動排進個人行事曆（接 AutoCal）。

## 核心概念鏈

**目標 → 知識依賴圖(DAG) → 每個節點的精選資源與順序 →（未來）排進行事曆**

## 已拍板的決策

| 項目 | 決定 | 理由 |
|---|---|---|
| 資料結構 | **有向無環圖 (DAG)，不是純樹** | 一個知識可能是多門知識的前置（例：空氣動力學同時是火箭與賽車的前置），純樹裝不下 |
| 節點欄位 | id / name / summary / prerequisites / level / estimatedHours / searchQuery / resources | `estimatedHours` 是未來接 AutoCal 排程的關鍵 |
| 連結來源 | **一律來自真實搜尋（Brave），LLM 只負責挑與排，不准生連結** | LLM 最不可靠的就是編造不存在的網址/書名/論文；搜尋引擎給的連結天生是真的 |
| 連結驗證 | 先相信搜尋結果，不逐一檢查能否開啟 | 省工；搜尋結果本來就不太會假 |
| MVP 範圍 | **先做：輸入目標 → 產樹 → 看資源清單。排程、個人化、漂亮的圖都先不做** | 先驗證最不確定的事：AI 產的內容到底有沒有用 |
| 第一步形式 | **先寫 Python 腳本（終端機），不碰 Xcode** | 內容品質用腳本一個下午就能驗；UI 做漂亮是之後的事，內容爛了做再漂亮也沒用 |
| 「人可調」 | 樹存成 JSON 檔，不滿意直接用文字編輯器改 | 最省力；之後再升級成點一點改 |
| 目標具體度 | **產樹前先反問 2~3 題**（AI 當場生問題） | 「學火箭」太發散；帶上社團的具體產出、現有程度、偏好，樹會小而精準 |
| 樹的深度 | 問到「現有程度」後，**停在使用者已經會的地方**，不往下挖到太基礎 | 否則會一路挖到小學數學，新手會崩潰 |
| 使用對象 | 先自己用，再慢慢開放給別人 | 自己用可以超級簡化，很多東西先不做 |
| 後端 | 沿用 AutoCal：家裡 GPU 跑的 LLM（192.168.0.45，退回 192.168.2.230）+ Brave Search | 自家後院發電，免費、隱私自己掌握、可以狂試不心疼 |

## 最大難點（誠實評估）

- 🔴 **最不可靠：資源「連結」** — LLM 很會編造不存在的網址。解法：連結只能來自真實搜尋。
- 🟡 **中等：知識樹「結構」** — LLM 組織通識骨架做得不錯，偶爾漏一兩個或排錯，可接受。
- 🟢 **還好：順序與摘要** — LLM 擅長。

### 新手的根本矛盾（心態，不是功能）
身為新手，我沒辦法判斷 AI 給的樹「有沒有漏掉重要的東西」。這是「新手驗證新手教材」
天生的困境。應對（當作使用心態，不寫進程式）：
1. 交叉比對：拿去跟學長姐、網路 roadmap 對一下。
2. 把樹當「超讚的起點」，不是「完美答案」。
3. 信任但查證：學下去跟不上，代表前面漏了前置，再回頭補。

> **期待值擺對**：AI 不保證完整，但給你一個比自己瞎找好得多的起點。

## 與 AutoCal 的關係

傾向：**先獨立開發，但設計成「能併回去」**。
- 新東西獨立做，不會弄壞現在能跑的 AutoCal。
- 後端 LLM / 搜尋邏輯刻意跟 AutoCal 用一樣的連法。
- 等知識樹驗證成功、要排程時，再把「知識樹 → 學習任務清單」丟給 AutoCal 的
  排程引擎（EventKit）。

## 路線圖

| 階段 | 做什麼 | 驗證什麼 |
|---|---|---|
| ① **現在（已開工）** | Python 腳本：目標 → 樹 + 真實資源連結 | 內容到底有沒有用 ←全部賭注在這 |
| ② | 樹存成檔案、能手動改 | 人機協作順不順 |
| ③ | 包成 iOS App（SwiftUI 用 List / DisclosureGroup 大綱，先不畫圖） | 自己天天用順不順 |
| ④ | 接 AutoCal，排進行事曆 | （本來最後才想要的） |
| ⑤ | 給別人用 | 最後的最後 |

## 技術方向

- **產樹**：LLM 一次生成整棵骨架（名稱 + 前置關係），不做逐層展開（MVP 不需要）。
- **找資源**：LLM 先給每個節點「該搜什麼關鍵字」→ Brave 真的去搜 → 真實結果再丟回
  LLM 篩選排序、標語言/類型/難度。連結永遠來自搜尋結果。
- **呈現**：MVP 終端機印大綱；之後 iOS 用可展開列表；畫圖是更後面的事。

## 如何執行腳本（knowtree.py）

```bash
# 設定 Brave 金鑰（和 AutoCal 用的同一把；不設也能跑，只是跳過找資源）
export BRAVE_API_KEY="你的金鑰"

python3 knowtree.py                       # 會問你想學什麼
python3 knowtree.py "造一台業餘固態火箭"    # 直接給目標
python3 knowtree.py "學賽車空氣力學" --no-search   # 只產樹、先不找資源（快）
```

- 需要能連到家裡 LLM 伺服器（VPN）。預設連 192.168.0.45，連不到自動退回 192.168.2.230。
- 換網路可用環境變數覆寫：`LLM_BASE_URL`、`LLM_MODEL`。
- 只用 Python 內建函式庫，不需要 `pip install`。
- 跑完會在當前資料夾存一個 `<目標>.knowtree.json`，可直接開來改。

## 待討論 / 未決

- 樹學完怎麼「驗收」有沒有真的學會？（MVP 先用自我標記 status，不做測驗）
- 多棵樹之間能不能共用節點？（例：火箭和賽車都要空氣動力學）
- 資源要不要支援「偏好中文 / 可接受英文」的開關？（目前在反問階段處理）
- 接 AutoCal 時，排程的粒度（每天幾小時、怎麼分配到節點）。
