# 審閱紀錄：home-input-redesign 第 1 輪（Codex gpt-6-astra，唯讀）

對象：規格書 v2.1。以下是 astra 的原始回覆，未經刪改。

已對照指定三個檔案，未修改任何檔案。以下行號指規格書。

API 核心寫法沒有問題：`glassEffect(.regular, in: RoundedRectangle(...))`、`.buttonStyle(.glassProminent)` 與 `.buttonStyle(.glass)` 均有對應 API；使用 Xcode 26 SDK 並在新版分支加上可用性檢查，可保留 iOS 17 部署目標。按鈕樣式輔助也必須包含檢查，不能只保護面板。[Apple 自訂玻璃效果文件](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)

**1）規格內部矛盾**

- **【中】舊版按鈕實作不符合驗收要求**（L49–55、L84）。`.borderedProminent`／`.bordered` 不保證具有毛玻璃材質，但驗收要求「面板與按鈕」皆呈現毛玻璃。**建議：**驗收改為「面板使用毛玻璃，按鈕使用指定系統退回樣式」，允許不同系統版本的視覺差異。
- **【中】強調色限制超出本次修改範圍**（L18、L23–24、L82）。驗收寫整個新增頁「只有主按鈕與游標」使用強調色，但 `RootView` 的選取分頁、設定齒輪及既有其他控制項未被排除。**建議：**將限制明確縮為「輸入區內」，並豁免既有導覽、分頁及結果區。
- **【低】禁止固定顏色與指定邊線顏色互相衝突**（L42、L74）。邊線指定 `.white`／`.black`，卻又要求全部使用語意色。**建議：**明列邊線為例外，或統一指定語意色及透明度。

**2）與現有程式碼不符或技術限制**

- **【中】「現有 AccentColor」資產不存在**（L51、L110）。實際 `Assets.xcassets` 只有目錄設定與 AppIcon，沒有 `AccentColor.colorset`。**建議：**明定沿用系統 `.accentColor`；若要新增品牌色資產，須同步擴大 L91 的允許變更範圍。
- **【中】純黑／純白的絕對要求不等同 `systemBackground`**（L33、L81）。系統背景是動態語意色，深色模式會依 base／elevated 情境調整，不能保證所有顯示情境都是 `#000000`。**建議：**改以「遵循 `systemBackground`」驗收，並說明純色要求只適用內容背景，是否包含導覽列與分頁列。[Apple 深色模式說明](https://developer.apple.com/design/human-interface-guidelines/dark-mode)
- **【中】導覽標題字重、字距缺少可行實作界線**（L34）。現況是 `ContentView.swift:126` 的 `.navigationTitle`；直接對內容套 `.bold`／`.tracking` 不會設定系統導覽標題。**建議：**保留系統大標題排版，明訂 `.navigationBarTitleDisplayMode(.large)`；若一定要自訂字距，須另外定義標題實作及允許修改範圍。

**3）遺漏的邊界情況**

- **【中】純換行輸入會讓按鈕可按，但操作沒有結果**（L57、L86）。`ContentView.swift:172、182` 僅移除 `.whitespaces`，而 `run()` 在 L41–42 移除 `.whitespacesAndNewlines`。**建議：**明定空字串、空格、Tab、純換行均停用；允許只修正 View 的停用條件，維持 ViewModel 不動。
- **【中】缺少鍵盤、長文字與窄視窗的組合情境**（L39、L71、L88–89）。`project.yml:37–41` 支援 iPad 四方向，但驗收未涵蓋橫向、分割畫面；也未定義超過八行、大字級與鍵盤同時出現時的行為。**建議：**要求游標可見、文字可捲動、按鈕可透過捲動到達；52pt 應為一般字級基準或最小高度，允許隨文字增高。
- **【中】既有非初始狀態缺少回歸案例**（L66、L86–87）。`isParsing` 也用於重新檢查衝突；`run()` 失敗時不清除舊項目，`save()` 部分失敗時成功與錯誤訊息可能同時存在。**建議：**加入「已有卡片再解析／搜尋」「重新檢查」「儲存部分失敗」案例，確認訊息、卡片、進度與加入列仍可操作。
- **【低】移除說明文字後未定義無障礙名稱**（L38–39）。placeholder 填入後消失，規格沒有要求固定的輸入欄位名稱。**建議：**指定持續有效的 `accessibilityLabel`，並驗證 VoiceOver 在空白與已有內容時均能辨識欄位用途。

**4）驗收條件無法客觀檢查**

- **【高】強制舊版分支不能取代 iOS 17 執行驗證**（L84、L99）。在 iOS 26 改走退回分支，只能檢查該分支外觀，不能驗證 iOS 17 的執行相容性與系統布局。**建議：**分列「iOS 17 實際執行」「iOS 26 執行」「強制退回分支預覽」；若沒有舊版執行環境，明列未驗證，不以截圖替代。
- **【中】視覺與尺寸標準缺少判定門檻**（L37、L48、L53、L83–89）。「約 150pt／52pt」「全寬或置中」「版面正常」「較大字級」容許多種結果。**建議：**固定次按鈕寬度策略、尺寸容差、裝置型號與 Dynamic Type 等級；以無重疊、無非預期截斷、控制項可到達等條件驗收。玻璃外觀附指定環境的核准參考圖。
- **【中】無障礙承諾與驗收不一致**（L77、L90）。設計要求降低透明度及增加對比時退回不透明背景，驗收卻只檢查降低透明度後可讀；「系統自動處理」也不能直接作為特定外觀的驗收證據。**建議：**分別測試兩項設定及同時開啟；明定要驗收「系統調適且可讀」或「完全不透明」。若要求後者，允許在系統效果未達標時加明確退回處理。

**5）任務拆得太大**

- **【中】任務 4 包含多個可獨立失敗的驗證工作**（L99）。同時混合系統版本、外觀、裝置尺寸、大字級與無障礙，而且「各截圖一次」未定義組合。**建議：**拆成「建置與版本相容」「尺寸／鍵盤／長文字」「外觀與無障礙」「功能回歸」四項，各附測試案例、通過條件與證據。任務 1–3 的粒度可接受。
