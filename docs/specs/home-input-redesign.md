# 規格書：新增頁輸入區改版（科技極簡 + Liquid Glass）

狀態：v3.1（使用者已同意方向；已納入 astra 兩輪審閱意見；待最終確認）
範圍檔案：只有 `AutoCal/ContentView.swift`。`GlassPanel` 修飾器與按鈕樣式輔助全部寫在此檔內，不新增檔案、不修改 `project.yml` 與專案檔（專案以 `project.yml` 產生，新增檔案會牽動專案檔，本次避免）。

變更紀錄：
- v1：iOS 原生群組灰風格（已作廢，使用者覺得色塊太陽春）
- v2：科技極簡、純黑／純白跟隨系統、Liquid Glass 質感
- v3.1：依 astra 複審——不新增檔案；`FakeProgressView` 列為強調色例外；驗收 8 改為「啟用／停用條件維持原狀」
- v3：依 astra 審閱修正——強調色範圍縮小至輸入區、改用系統背景與系統強調色、保留系統大標題、修正純換行停用條件、驗收與任務拆細

## 1. 背景與目標

使用者覺得現在的新增頁「太單調、太空、太像系統預設、顏色不好看」。

目標風格：科技極簡。
- 淺色模式為白底，深色模式為黑底，完全跟隨系統設定（使用 `systemBackground`），不自己加切換。
- 沒有彩色色塊。畫面靠留白、字體大小層次、細線條與玻璃質感建立設計感。
- 有 iPhone 的 Liquid Glass 質感：輸入區與按鈕像半透明的玻璃，有折射與高光，不是平面色塊。
- 輸入區內只用一個強調色（系統強調色），克制使用，只用在主按鈕與游標。既有的導覽、分頁列、結果區，以及解析中的 `FakeProgressView`（維持原樣，含其系統強調色進度條）不在此限制內。

## 2. 非目標（這次不做）

- 不改解析後的確認卡片（`ReviewSection`、`ReviewList.swift`）
- 不改底部「加入」列（`ReviewAddBar`）
- 不改行事曆頁、設定頁、分享擴充（AutoCalShare）
- 不改任何邏輯（`InputViewModel` 完全不動）
- 不新增圖片、字型、第三方套件
- 不調整最低支援版本（維持 iOS 17.0）
- 不做使用者自選主題的設定項目

## 3. 設計規格

### 3.1 整頁背景
- 使用 `Color(.systemBackground)`：淺色為白、深色為黑。不自行寫死色碼，也不覆寫 `userInterfaceStyle`（需確認 Info.plist 與程式中沒有寫死外觀）。
- 導覽標題維持系統的 large title（`.navigationBarTitleDisplayMode(.large)`），沿用現有標題文字「Just Add 記吧」，不自訂字重與字距。

### 3.2 輸入區（玻璃面板）
- 一個大的圓角玻璃面板，圓角 28，內距 20，最小高度約 150pt。
- 面板內只有輸入框，沒有說明小字。
- 輸入框：多行，`lineLimit(4...8)`，字體 `.title3`，無邊框無底色，placeholder 為 `下週三晚上七點跟小明吃火鍋`，placeholder 用 `.secondary` 色。超過八行時輸入框內可捲動；鍵盤出現時游標必須可見。
- 輸入框要有固定的 `accessibilityLabel`（例如「輸入想安排的行程或待辦」），不能依賴 placeholder（輸入後 placeholder 會消失）。
- 玻璃效果的實作（兩段式，必須都做）：
  - iOS 26 以上：用 `glassEffect(.regular, in: RoundedRectangle(cornerRadius: 28))`。
  - iOS 17～25：用 `.ultraThinMaterial` 加 0.5pt 的細邊線。邊線顏色是「不使用語意色」的唯一例外：深色 `.white.opacity(0.15)`、淺色 `.black.opacity(0.08)`，用 `@Environment(\.colorScheme)` 判斷。
  - 用 `if #available(iOS 26, *)` 包起來，抽成可重用的 `ViewModifier`（建議命名 `GlassPanel`），不要把版本判斷散在各處。
- 整頁背景保持純色，不加漸層或圖片；玻璃質感完全由系統效果提供。

### 3.3 按鈕
- 主按鈕「解析」：
  - 全寬、最小高度 52pt（字級放大時允許變高）、膠囊形。
  - iOS 26 以上：`buttonStyle(.glassProminent)`。
  - iOS 17～25：`buttonStyle(.borderedProminent)` + 膠囊形（`.buttonBorderShape(.capsule)`）。
  - 圖示 `wand.and.stars`，使用系統預設強調色（`.accentColor`）。專案沒有 `AccentColor.colorset`，本次不新增色彩資產。
- 次要按鈕「搜尋網路活動」：
  - 全寬、最小高度 46pt、膠囊形（寬度策略固定為全寬）。
  - iOS 26 以上：`buttonStyle(.glass)`。
  - iOS 17～25：`buttonStyle(.bordered)` + 膠囊形。
  - 圖示 `globe`，文字與圖示用 `.primary` 色（黑白自動切換），不用強調色。
- 停用條件：輸入去除空格、Tab 與換行（`.whitespacesAndNewlines`）後為空時，兩個按鈕都停用。這與 `InputViewModel.run()` 的判斷一致；允許只修改 View 內的停用條件，`InputViewModel` 不動。

### 3.3.1 設定按鈕（右上角齒輪）
- 維持位置與功能（開啟設定頁）。
- iOS 26 以上：系統導覽列的工具列按鈕本身即為玻璃樣式，不額外處理。
- iOS 17～25：維持現有系統樣式即可，不額外處理。
- 底部「新增／行事曆」分頁列（`RootView.swift`）不修改；iOS 26 以上由系統自動呈現 Liquid Glass。

### 3.4 解析中狀態
- 解析中時，兩個按鈕位置顯示原有的 `FakeProgressView`，文字與邏輯不變。

### 3.5 其他不變的行為
- 成功訊息（含「復原」按鈕）與錯誤訊息的位置不變。此區不改樣式（綠、橘維持現狀），不在本次範圍。
- 點空白處、往下滑收起鍵盤，以及鍵盤上方的「完成」按鈕：不變。
- iPad / Mac 上寬度上限 640 並置中：不變。

### 3.6 深色模式與無障礙
- 全部使用系統語意顏色與系統材質，不寫死色碼（唯一例外見 3.2 的舊版邊線）。
- 玻璃面板上的文字對比必須足夠（`.primary` 與 `.secondary`）。
- 支援 Dynamic Type。
- 輔助使用：「降低透明度」與「增加對比」開啟時，面板與按鈕必須清楚可讀。預期由系統的 `.ultraThinMaterial` 與 `glassEffect` 自動調適；若驗證時發現不可讀，才加入明確的不透明退回處理。

## 4. 驗收條件

測試環境：iPhone SE（小螢幕）、一款大尺寸 iPhone、iPad（含橫向）；iOS 26 模擬器必測；iOS 17 模擬器或實機若取得不到，驗收報告必須明寫「iOS 17 實機執行：未驗證」，不能用強制舊版分支的截圖代替。

外觀
1. 淺色模式新增頁為白底，深色模式為黑底；切換系統外觀後立即跟隨。
2. 輸入區內沒有彩色大色塊，只有主按鈕與游標使用強調色（`FakeProgressView` 維持原樣，為例外）。
3. iOS 26：輸入面板與兩個按鈕呈現 Liquid Glass（半透明、有高光），並附模擬器截圖。
4. 舊版路徑（把可用性判斷暫時改為 false，只用來預覽退回外觀）：面板為毛玻璃、按鈕使用指定的系統樣式，版面與 iOS 26 一致、無缺漏。
5. 輸入框無邊框，空白時顯示 placeholder，畫面不再有獨立說明小字；VoiceOver 在空白與已有內容時都能唸出輸入欄用途。

行為（與改版前完全相同，回歸測試）
6. 輸入為空、只有空格、只有 Tab、只有換行時，兩個按鈕都不可按；有實際文字時都能按。
7. 解析、搜尋、確認卡片、加入、復原都正常。
8. 畫面上已有確認卡片時再次解析／搜尋、重新檢查衝突，進度元件、訊息、卡片與加入列都顯示正常，且各控制項的啟用／停用條件與改版前完全相同（例如 `ReviewSection` 在 `isBusy` 時停用重新檢查按鈕，維持不變）。
9. 儲存部分失敗時，錯誤訊息與成功訊息顯示行為與改版前一致。

版面
10. 在上述三種裝置上，沒有控制項重疊、沒有非預期的文字截斷，所有按鈕都能操作（可透過捲動到達）。
11. Dynamic Type 設為「AX3」時，畫面仍可使用；超過八行的長文字可在輸入框內捲動；鍵盤出現時游標可見、按鈕可用捲動到達。
12. 開啟「降低透明度」、開啟「增加對比」、兩者同時開啟，面板與按鈕文字都清楚可讀。

工程
13. `git diff` 只涉及 `AutoCal/ContentView.swift`、本規格書與必要的 skill 文件；沒有新增檔案，`project.yml` 與專案檔無改動；`InputViewModel` 無改動。
14. 專案以 Xcode 26 成功建置，最低部署目標仍為 iOS 17.0。

## 6. 風險與備註

- `glassEffect`、`.glass`、`.glassProminent` 需要 iOS 26 SDK（本機 Xcode 26.6 已具備）。所有使用處都必須有 `#available(iOS 26, *)` 檢查，按鈕樣式輔助同樣要檢查。
- `onTapGesture { inputFocused = false }` 套在 ScrollView 上，改版後要確認點輸入框內不會誤收鍵盤。
- Liquid Glass 在純色背景上效果較含蓄；若使用者覺得不夠「液態」，下一版可評估加入極淡的背景光暈，這次不做。
- 本規格書定案前，不要開始寫程式。
